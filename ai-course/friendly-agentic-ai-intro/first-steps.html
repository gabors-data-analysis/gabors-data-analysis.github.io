First Steps

Put the agent to work on what you know: a Word draft, a pile of readings, and a small dataset whose numbers you check yourself

⌂ Overview 1 Setup 2 First steps 3 Staying in charge 4 A paper in 50 minutes

What do we do in this part?

In this part the agent works on three things from your everyday work: a draft in Word, a handful of papers in PDF, and a small public dataset. There is a reason for this choice. You can judge the agent’s work only where you know the answer. On a draft you wrote and on papers you have read, you will see at once what is useful, what is generic and what is wrong.

Between the first and the second task, we give the agent two things that make it more reliable: standing instructions, and two skills.

We assume you have finished Part 1: the app works, first-project is open in the Code tab in Manual mode, Python is set up, and Typora opens .md files.

NoteWhat you will have at the end

2.1 Work on a Word document

Most of your writing, and your coauthors’, lives in Word. The agent can read, comment on, edit and create Word files. The routine below keeps you in control: the agent never touches your original, and you see each change as a tracked change in Word.

To get ready, copy a Word document you know well (a draft, a proposal, a referee report) into a docs/ subfolder. Pick one that is not confidential.

Ask for comments, not changes

This is the safest start, because nothing is edited.

Read docs/draft.docx. Do not change it.
Give me the ten most important comments on the argument, structure and clarity, most important first. For each, say which section or paragraph it refers to. Save the list as docs/draft_comments.md.

Open the list in Typora. Some comments will be useful, some generic, and a few wrong. That mix tells you a lot about how to use the agent.

Ask for edits, then review them as tracked changes

Make a copy of docs/draft.docx called docs/draft_v2.docx. In the copy only: fix grammar and typos, and split sentences longer than 40 words.
Do not change the argument, the citations or the numbers. Keep all formatting, footnotes and comments.
When done, list the kinds of changes you made.

Then let Word show what changed.

  1. In desktop Word (the browser version can’t compare), go to the Review tab, click Compare, then Compare… (Windows) or Compare Documents (Mac).
  2. As Original document, choose draft.docx. As Revised document, choose draft_v2.docx.
  3. Word opens a new document with each change as a tracked change. Accept or reject them as you would a coauthor’s.

This is the Word review you already use. Also, the comparison shows every change, including the ones you didn’t ask for.

Write in Markdown, finish in Word

For new text (a memo, a section, a report), we advise drafting and revising in Markdown with the agent, and converting to Word at the end. The agent works best in plain text, and its changes are easier to follow there.

TipTry it: what the agent sees

Right-click a Word file and open it with Notepad (on Windows). What you see is unreadable: a .docx is a packed bundle of files. Before the agent can work with it, it has to unpack and convert it, which costs time and loses some structure. Now open a Markdown file the same way: it reads just as it does in Typora. On a Mac, or on any computer, you can ask the agent instead: “Show me the first 20 lines of docs/draft.docx exactly as stored on disk, without converting it.”

The idea comes from Simon Martin’s slides Jump-starting AI agents.

Convert docs/memo.md to docs/memo.docx. Use docs/my-template.docx for the styles (fonts, headings, margins).

For my-template.docx, use any Word file whose look you like, such as your university template or a past paper. The agent copies its styles, not its text.

Comments in the margin

You can also ask: “Put your comments as Word comments in the margin of docs/draft_v2.docx.” This usually works. If the result looks odd, use the list in Markdown instead.

2.2 Give the agent standing instructions: AGENTS.md

Each session starts from zero: the agent doesn’t remember yesterday. So it is good practice to write down once what it should always know: who you are, how you work, and what it must never do. This file is called AGENTS.md. It sits in the project folder, and the agent reads it at the start of every session.

We prepared a starter file based on how we work with agents. Ask the agent to fetch it and to create the folders:

Download this file exactly (use a download command, do not retype it) and save it as AGENTS.md in this folder:
https://raw.githubusercontent.com/gabors-data-analysis/da-w-ai/main/friendly-agentic-ai-intro/starter/AGENTS.md

Then create the folders it describes (data/raw, data/clean, code, output, docs) and summarize the instructions for me in five bullet points.

Then open AGENTS.md in Typora and edit the “About me” section. It is your file.

NoteWhat is in the starter AGENTS.md (click to open) 
# Instructions for the AI agent in this project

The agent reads this file at the start of every session. Edit it freely.
When the agent makes the same mistake twice, add a line here.

## About me

- I am a social scientist (EDIT: field, e.g. sociology, political science, economics).
- I have used AI as a chatbot, mostly for text. I have not written code before.
- Explain what you do in plain language. The first time you use a technical term,
  give a one-line definition.
- Use Python for code, unless I ask for R or Stata.

## How to work with me

- For any task with more than a few steps, first show me a short plan and wait for my OK.
- Do the smallest thing that answers my request. Ask before adding extras.
- Work in small steps. Stop at natural break points and tell me what you did and what is left.
- If my request is unclear, ask one question rather than guessing.
- When you finish, say what you did not do or could not check.
- Keep `status.md` up to date: what is done, what is open, what comes next.
  Update it at the end of each task. When I say "continue", read it first.

## Safety with my files

- Never delete files. If something should go, move it to `_old/` and tell me.
- Never change anything in `data/raw/`. Raw data stays as it arrived.
- Never overwrite a Word, Excel or PDF file I gave you. Save your changes as a new
  file with `_v2` (or the next number) at the end of the name.
- Install Python packages only inside this project's environment (`.venv`).
  Ask before installing anything for the whole computer.
- Do not upload my files or data to any website or online service.

## Data and numbers

- Never make up numbers, references, quotes or sources. If you cannot verify something, say so.
- When you report a number, say where it comes from (which file, which script, which web page).
- Check your own results: count rows before and after each step, and compare a few
  values by hand with the source.
- Log analytical choices in `DECISIONS.md` (see the `decision-log` skill).

## Folders and files

- `data/raw/` original data, never edited
- `data/clean/` cleaned data, produced by code
- `code/` scripts, numbered in the order they run: `01_get_data.py`, `02_clean.py`, ...
- `output/` figures (PNG) and tables
- `docs/` notes, memos and drafts. Write new text in Markdown (`.md`);
  convert to Word only when I ask.
- Every result must be reproducible: running the scripts in order rebuilds all outputs.

## Writing

- Plain, direct prose. Short sentences. No hype words (delve, crucial, landscape,
  comprehensive, shed light on).
- Say what the data shows, then the caveats. Talk about associations, not effects,
  unless the design allows a causal reading.

## PDFs

- To read a PDF, first extract its text to a `.txt` file, then work from the text
  (see the `read-pdf` skill).

What does it say? Plan before longer tasks. Do the smallest thing that answers the request. Never delete: move files to _old/. Never overwrite raw data or your Word files. Never invent numbers or references, and say where each number comes from. Check results by hand. Log analytical decisions. Keep a short progress note, status.md, so the next session can pick up where this one stopped.

Grow the file slowly. When the agent makes the same mistake twice, add one line. After a month it will fit how you work better than any template.

2.3 Add two skills

A skill is a recipe for one type of task: a Markdown file called SKILL.md in its own folder. The agent uses a skill when the task matches its description, or when you type / and its name.

We start with two.

decision-log records every analytical choice in a file called DECISIONS.md: dropped observations, variable definitions, methods. For each choice it notes the alternatives and the basis: evidence, convention, your instruction, or just a default. Read this file before you trust the results.

read-pdf makes the agent extract a PDF’s text to a .txt file first and work from that, with page numbers. This prevents the most common failure with PDFs: answering from a partly read document without saying so.

NoteThe decision-log skill (click to open) 
---
name: decision-log
description: Keep a DECISIONS.md log of the analytical choices made during data work (which observations to keep, how a variable is defined, which method, which chart), so the researcher can review the reasoning before trusting results. Use whenever cleaning data, building a sample, defining variables, choosing a method or designing a table or figure, even if the user does not mention it. Also use when the user asks "what did you decide?" or "review the decisions".

# Decision log

Every result rests on judgment calls the reader never sees. The researcher needs to
check those calls *before* looking at results. This skill keeps them in one file,
`DECISIONS.md` in the project folder, written as the decisions are made.

## What to log

Log a decision when a reasonable analyst could have chosen differently AND the choice
could change the results or how we read them. Examples:

- dropping observations (missing values, outliers, small groups, a year or a country)
- defining a variable (what counts as "employed", income in levels or logs, which year's prices)
- merging tables (which key, what to do with rows that do not match)
- choosing a method (mean or median, which regression, which controls)
- designing an exhibit (what goes in the main chart, what is left out)

Do not log mechanical steps with no real alternative, or formatting.

## Format

Create `DECISIONS.md` on first use. Keep a summary table on top and a short entry for each
decision below it. Number entries D1, D2, ... and never renumber or delete them.

```markdown
# Decision log

| ID | Date | Decision | Basis | Status |
|----|------|----------|-------|--------|
| D1 | 2026-11-06 | Drop respondents younger than 18 | user | decided |

## D1 - Drop respondents younger than 18
- **Decision point:** The survey includes 16-17 year olds; the question is about adult voters.
- **Chosen:** Keep age 18 and above (drops 412 of 9,870 rows).
- **Alternatives:** keep all (rejected: they cannot vote); keep 16+ (only where voting age is 16).
- **Basis:** user instruction, 2026-11-06.
- **Affects:** all tables and figures. Easy to reverse.
```

The **Basis** field matters most. Be honest about it:

- `evidence` a check was run (name the file or the numbers)
- `convention` common practice in the field (name the source)
- `user` the researcher asked for it (give the date)
- `default` chosen for convenience, not tested. This label is the most useful one for the
  reviewer, because it shows where to look first.

**Status** is `decided`, `provisional` (to make progress, revisit later) or `needs-review`.

## How to work

1. Write the entry when the decision is made, not at the end.
2. If a decision drops a lot of data, changes the main finding, or is hard to undo,
   mark it `needs-review` and tell the user in plain words before going on.
3. If a decision is reversed, add a new entry and mark the old one `superseded by Dn`.
4. When the user asks to review the log, list first the `default` and `provisional`
   decisions that many results depend on.

# Read a PDF: text first

Reading a PDF directly is unreliable: long files get cut, columns get mixed up, and the
agent may answer from a partial view without saying so. So we always extract the text
first, save it, and work from the saved text.

## Steps

1. **Extract the text.** Use the Python package `pymupdf` in this project's environment
   (install it with the project's package manager if missing). Save the text next to the
   PDF with the same name and a `.txt` ending, for example `paper.pdf` -> `paper.txt`.
   Mark each page with a line like `=== page 7 ===` so page numbers can be cited.
2. **Check the extraction.** Report the number of pages and the number of characters.
   If a page has almost no text (under ~200 characters), it is probably a scanned image.
   For those pages, render them to PNG (150 dpi is enough) and read the images.
   Tell the user which pages were read as images.
3. **Work from the `.txt` file**, not the PDF. For long documents (more than ~40 pages),
   read it section by section rather than all at once.
4. **Cite page numbers** for every claim, number or quote taken from the document.
   Quote exactly; never paraphrase inside quotation marks.
5. **Tables:** when the user needs a table, copy it into a CSV in `data/raw/` and then
   check three numbers from the CSV against the page image.

## What to tell the user at the end

- what was extracted (pages, characters, any pages read as images)
- where the `.txt` file is
- anything that could not be read well (garbled tables, formulas, footnotes)

Install them with this prompt:

Download these two files exactly (use a download command, do not retype them):
https://raw.githubusercontent.com/gabors-data-analysis/da-w-ai/main/friendly-agentic-ai-intro/starter/skills/decision-log/SKILL.md
https://raw.githubusercontent.com/gabors-data-analysis/da-w-ai/main/friendly-agentic-ai-intro/starter/skills/read-pdf/SKILL.md

Save them as .claude/skills/decision-log/SKILL.md and .claude/skills/read-pdf/SKILL.md inside this project folder. Then tell me in two sentences what each skill does.

Folders starting with a dot, like .claude, are hidden by default, so you may not see it in Explorer or Finder.

It worked if you start a new session (+ or New session), type /, and both skills show up in the list.

2.4 Read a pile of papers

Every project starts with reading, and reading is where a chatbot was already of some help. The agent adds two things. It works through a whole folder of papers in one go, and it leaves behind a table that you can check, line by line.

To get ready, make a folder docs/readings/ and copy five to ten PDFs into it. Choose papers you know well. Start a new session and send:

Use the read-pdf skill on every PDF in docs/readings/.
Then make a table with one row per paper: authors and year, research question, data or material, method, main finding. For each item, give the page number where you found it.
For each paper, add one sentence quoted word for word that states the main finding, with its page number.
If a paper does not state something, write "not stated". Do not guess, and do not use what you know about the paper from elsewhere.
Save the table as docs/readings.md.

Then check it. Open docs/readings.md in Typora and do three things.

  1. Pick two papers. Open each PDF at the page given, and search for the quoted sentence (Ctrl+F, or Cmd+F on a Mac). Is it there, word for word?
  2. Read the row of the paper you know best. Is this how you would summarize it to a colleague?
  3. Look at one “not stated”. Is it really not in the paper?

Why the fuss about quotes? Summarizing is what these models do best, and the table will look convincing. The typical mistake is a different one: a paraphrase presented as a quote, or a finding that comes from the model’s general knowledge and not from the file. A page number and a word-for-word quote make both mistakes easy to catch. In a published paper, a quote that doesn’t exist is the kind of error that readers remember.

Now ask a question across the papers: “Which of these papers disagree with each other, and on what? Give page numbers.” Judge the answer as you would judge a memo from a research assistant.

TipInterviews, field notes, open-ended answers

The same routine works on your own qualitative material: transcripts, field notes, open-ended survey answers. Ask for themes, each with word-for-word quotes, the file name and the line. But note that such material is usually confidential. Check your consent forms and your data agreement before any of it goes into the folder (Step 1.2).

2.5 Do a first task with data

Now it all comes together. Our question is simple: in EU countries where more women work, do women also hold more seats in parliament?

Start a new session and, before you send the prompt, switch the permission mode to Plan. In Plan mode the agent proposes but changes nothing until you agree.

Using the World Bank's open data (its API, no key needed), get for all EU countries for 2023:
- the share of seats held by women in the national parliament (%)
- the female labor force participation rate (% of women aged 15 and over)

Save the raw download in data/raw, write the code in code/, and make one scatter plot (participation on the x axis, seats in parliament on the y axis, with country labels) saved in output/.
Then write a half-page memo in docs/memo.md: what the chart shows, and three caveats.
Keep the decision log as you go.

Read the plan, and say plainly if something looks off. When you are happy with it, switch back to Manual and tell the agent to go ahead.

Then check it. This is your job, not the agent’s.

  1. Open the chart. Are the countries where you expected them to be?
  2. Pick two countries and look up their numbers on data.worldbank.org. Do they match the CSV file in data/raw?
  3. Read DECISIONS.md. The World Bank has more than one measure of labor force participation. Which one did the agent pick, and did it tell you? Which countries had no 2023 data, and what did it do about them?
  4. Read the memo. Does it say “effect” or “causes”? It shouldn’t. A scatter plot of 27 countries shows an association.

If you find a mistake, tell the agent, and add a line to AGENTS.md if it could happen again. Finally, ask for the memo as a Word file (Step 2.1).

Note what happened in check 3. The agent made a choice that you didn’t know existed. Nothing is wrong with that, as long as the choice is written down and you read it.

What habits make it work?

These habits are not technical. They are what you would ask of a careful research assistant, and of yourself.

NoteSix habits
  1. Plan first. For anything longer than a few minutes, use Plan mode. It is much cheaper to fix a plan than to fix finished work.
  2. Small steps. Ask for one thing, check it, then ask for the next. An agent running on a vague task produces plausible-looking work that you then have to read.
  3. Check against the source. Compare a few numbers and a few quotes with the source by hand, every time.
  4. Never let it delete or overwrite. Raw data and original documents stay untouched, and old files go to _old/. Then every mistake can be undone.
  5. One session per task. Long sessions get muddled. Start a new one for each task. What must carry over goes in a file: standing rules in AGENTS.md, analytical choices in DECISIONS.md, and where the work stands in status.md. End a session with “Update status.md.” Start the next with “Read status.md and continue where we left off.”
  6. Ask it to explain. “Why did you do that?” “What could go wrong here?” You are responsible for the work, so you need to understand it.

Troubleshooting

Problem What to do
Word Compare shows changes everywhere The agent probably rebuilt the whole document. Ask it to start again from a fresh copy and change only the text
The skills don’t show up when I type / Start a new session. Skills load when a session starts
A PDF comes out as nonsense, or nearly empty It is probably a scan. Tell the agent, and the read-pdf skill reads those pages as images. Check such papers with extra care
The agent seems stuck, or keeps doing the wrong thing Click stop and say plainly what you want. If the session is long, start a new one
It made a mess of my files Ask: “List every file you created or changed in this session.” Then ask it to move the unwanted ones to _old/
An error I don’t understand Paste it in and ask: “Explain this error simply, then fix it.”
