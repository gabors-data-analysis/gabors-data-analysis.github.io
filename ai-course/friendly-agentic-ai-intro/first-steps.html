First Steps

One small project, from a pile of papers to a reviewed memo, and how to stay in charge at every step

⌂ Overview 1 Setup 2 First steps 3 A paper in 50 minutes A Assignment 4 After the course 5 Go further 6 AI in science

What do we do in this part?

We run one small project from start to finish. The question: do big events change when babies are born? Newspapers love the story of a baby boom nine months after a big match or a blackout. Researchers in sociology, demography, medicine and economics have checked it, and they don’t all agree.

We prepared six papers on this question. The agent collects them, makes an extract of each, answers your questions about them, and writes a one-page memo. You review the memo the way you review a colleague’s draft, with comments on a PDF, and the agent revises it. At the end, a short task with data.

The six steps in about a minute. No sound. Open it full screen

Two ideas run through the whole part.

The agent works from material in the folder, not from memory. The overview explains why, in What is an AI agent?

You stay in charge. An agent is a tool that acts, and a tool that acts needs supervision, just as a research assistant does. So each step ends with a short box on staying in charge: how to set its limits, see what it did, agree the checks, and keep the final say. None of this needs coding. It needs the habits of a careful researcher.

We assume you have finished Part 1: the app works, first-project is open in the Code tab in Manual mode, Python is set up, and Typora opens .md files.

How does this part run?

The class takes an hour. We explain a few ideas, then you work on your own laptop: this is playtime. The rest you do after class.

When What Time
Before class Part 1, and Step 2.1: the ground rules about an hour, at home
In class: we explain The project, the files, permissions, staying in charge 15 minutes
In class: playtime Steps 2.2 to 2.4: collect the six papers, make extracts, ask them questions 35 minutes
In class: debrief What worked, what didn’t 10 minutes
After class Steps 2.5 and 2.6: the memo and its review, and a separate assignment with data about an hour

If you work through this part on your own, simply follow the steps in order.

NoteWhat you will have at the end

2.1 Set the ground rules

Before class

Each session starts from zero: the agent doesn’t remember yesterday. So it is good practice to write down once what it should always know: who you are, how you work, and what it must never do. This file is called AGENTS.md. It sits in the project folder, and the agent reads it at the start of every session.

The second tool is a skill: a recipe for one type of task, written as a Markdown file called SKILL.md in its own folder. The agent uses a skill when the task matches its description, or when you type / and its name. We start with two.

  • read-pdf makes the agent extract a PDF’s text to a .txt file first and work from that, with page numbers. This prevents the most common failure with PDFs: answering from a partly read document without saying so.
  • decision-log records every analytical choice in a file called DECISIONS.md: dropped observations, variable definitions, methods. For each choice it notes the alternatives and the basis: evidence, convention, your instruction, or just a default.

We prepared both, and a starter AGENTS.md. One prompt sets everything up:

Download these three files exactly (use a download command, do not retype them):
https://raw.githubusercontent.com/gabors-data-analysis/da-w-ai/main/friendly-agentic-ai-intro/starter/AGENTS.md
https://raw.githubusercontent.com/gabors-data-analysis/da-w-ai/main/friendly-agentic-ai-intro/starter/skills/read-pdf/SKILL.md
https://raw.githubusercontent.com/gabors-data-analysis/da-w-ai/main/friendly-agentic-ai-intro/starter/skills/decision-log/SKILL.md

Save the first as AGENTS.md in this folder, and the two skills as .claude/skills/read-pdf/SKILL.md and .claude/skills/decision-log/SKILL.md.
Then create the folders that AGENTS.md describes, and summarize its instructions for me in five bullet points.

Then open AGENTS.md in Typora and edit the “About me” section. It is your file. Folders starting with a dot, like .claude, are hidden by default, so you may not see that one in Explorer or Finder.

It worked if you start a new session (+ New in the sidebar, or Ctrl+N; Cmd+N on a Mac), type /, and both skills show up in the list.

AGENTS.md

# Instructions for the AI agent in this project

The agent reads this file at the start of every session. Edit it freely.
When the agent makes the same mistake twice, add a line here.

## About me

- I am a social scientist (EDIT: field, e.g. sociology, political science, economics).
- I have used AI as a chatbot, mostly for text. I have not written code before.
- Explain what you do in plain language. The first time you use a technical term,
  give a one-line definition.
- Use Python for code, unless I ask for R or Stata.

## How to work with me

- For any task with more than a few steps, first show me a short plan and wait for my OK.
- Do the smallest thing that answers my request. Ask before adding extras.
- Work in small steps. Stop at natural break points and tell me what you did and what is left.
- If my request is unclear, ask one question rather than guessing.
- When you finish, say what you did not do or could not check.
- Keep `status.md` up to date: what is done, what is open, what comes next.
  Update it at the end of each task. When I say "continue", read it first.

## Safety with my files

- Work only inside this project folder. If a step needs anything outside it, stop,
  tell me what and why, and wait for my OK.
- Never delete files. If something should go, move it to `_old/` and tell me.
- Never change anything in `data/raw/`. Raw data stays as it arrived.
- Never overwrite a Word, Excel or PDF file I gave you. Save your changes as a new
  file with `_v2` (or the next number) at the end of the name.
- Install Python packages only in this project's environment (`.venv`, or where
  `docs/SETUP-NOTES.md` says it is). Ask before installing anything for the whole computer.
- Do not upload my files or data to any website or online service.

## Data and numbers

- Never make up numbers, references, quotes or sources. If you cannot verify something, say so.
- When you report a number, say where it comes from (which file, which script, which web page).
- Check your own results: count rows before and after each step, and compare a few
  values by hand with the source.
- Log analytical choices in `DECISIONS.md` (see the `decision-log` skill).
- Do every step that reads, changes or creates data in a script in `code/`, never as a
  one-off command. Start each script with a short comment in plain language: what it
  reads, what it does, and what it writes.

## Sources and quotes

- Work from the files in this folder, not from memory. If the answer is not in the
  files, say "not in the files".
- Every quote must be word for word from a file in this folder, with the file name and page.
- Every reference must be a file in this folder or have a DOI that opens.

## Folders and files

- `data/raw/` original data, never edited
- `data/clean/` cleaned data, produced by code
- `code/` scripts, numbered in the order they run: `01_get_data.py`, `02_clean.py`, ...
- `output/` figures (PNG) and tables
- `docs/readings/` papers as PDFs, with their extracted text; never edit the PDFs
- `docs/extracts/` one Markdown summary per paper
- `docs/` notes, memos and drafts. Write new text in Markdown (`.md`);
  convert to Word only when I ask.
- Every result must be reproducible: running the scripts in order rebuilds all outputs.

## Writing

- Plain, direct prose. Short sentences. No hype words (delve, crucial, landscape,
  comprehensive, shed light on).
- Say what the data shows, then the caveats. Talk about associations, not effects,
  unless the design allows a causal reading.

## PDFs

- To read a PDF, first extract its text to a `.txt` file, then work from the text
  (see the `read-pdf` skill).

The read-pdf skill

---
name: read-pdf
description: Read a PDF (paper, report, book chapter, questionnaire, codebook) reliably by first extracting its text into a .txt file and then working from that text. Use whenever the user asks to read, summarize, quote, compare or extract information or tables from a PDF.
---

# Read a PDF: text first

Reading a PDF directly is unreliable: long files get cut, columns get mixed up, and the
agent may answer from a partial view without saying so. So we always extract the text
first, save it, and work from the saved text.

## Steps

1. **Extract the text.** Use the Python package `pymupdf` in this project's environment
   (install it with the project's package manager if missing). Save the text next to the
   PDF with the same name and a `.txt` ending, for example `paper.pdf` -> `paper.txt`.
   Mark each page with a line like `=== page 7 ===` so page numbers can be cited.
2. **Check the extraction.** Report the number of pages and the number of characters.
   If a page has almost no text (under ~200 characters), it is probably a scanned image.
   For those pages, render them to PNG (150 dpi is enough) and read the images.
   Tell the user which pages were read as images.
3. **Work from the `.txt` file**, not the PDF. For long documents (more than ~40 pages),
   read it section by section rather than all at once.
4. **Cite page numbers** for every claim, number or quote taken from the document.
   Quote exactly; never paraphrase inside quotation marks.
5. **Tables:** when the user needs a table, copy it into a CSV in `data/raw/` and then
   check three numbers from the CSV against the page image.

## What to tell the user at the end

- what was extracted (pages, characters, any pages read as images)
- where the `.txt` file is
- anything that could not be read well (garbled tables, formulas, footnotes)

The decision-log skill

---
name: decision-log
description: Keep a DECISIONS.md log of the analytical choices made during data work (which observations to keep, how a variable is defined, which method, which chart), so the researcher can review the reasoning before trusting results. Use whenever cleaning data, building a sample, defining variables, choosing a method or designing a table or figure, even if the user does not mention it. Also use when the user asks "what did you decide?" or "review the decisions".
---

# Decision log

Every result rests on judgment calls the reader never sees. The researcher needs to
check those calls *before* looking at results. This skill keeps them in one file,
`DECISIONS.md` in the project folder, written as the decisions are made.

## What to log

Log a decision when a reasonable analyst could have chosen differently AND the choice
could change the results or how we read them. Examples:

- dropping observations (missing values, outliers, small groups, a year or a country)
- defining a variable (what counts as "employed", income in levels or logs, which year's prices)
- merging tables (which key, what to do with rows that do not match)
- choosing a method (mean or median, which regression, which controls)
- designing an exhibit (what goes in the main chart, what is left out)

Do not log mechanical steps with no real alternative, or formatting.

## Format

Create `DECISIONS.md` on first use. Keep a summary table on top and a short entry for each
decision below it. Number entries D1, D2, ... and never renumber or delete them.

```markdown
# Decision log

| ID | Date | Decision | Basis | Status |
|----|------|----------|-------|--------|
| D1 | 2026-11-06 | Drop respondents younger than 18 | user | decided |

## D1 - Drop respondents younger than 18
- **Decision point:** The survey includes 16-17 year olds; the question is about adult voters.
- **Chosen:** Keep age 18 and above (drops 412 of 9,870 rows).
- **Alternatives:** keep all (rejected: they cannot vote); keep 16+ (only where voting age is 16).
- **Basis:** user instruction, 2026-11-06.
- **Affects:** all tables and figures. Easy to reverse.
```

The **Basis** field matters most. Be honest about it:

- `evidence` a check was run (name the file or the numbers)
- `convention` common practice in the field (name the source)
- `user` the researcher asked for it (give the date)
- `default` chosen for convenience, not tested. This label is the most useful one for the
  reviewer, because it shows where to look first.

**Status** is `decided`, `provisional` (to make progress, revisit later) or `needs-review`.

## How to work

1. Write the entry when the decision is made, not at the end.
2. If a decision drops a lot of data, changes the main finding, or is hard to undo,
   mark it `needs-review` and tell the user in plain words before going on.
3. When a rule drops observations, say what it removed: how many rows, and which units
   by name when they are few (a country, a year, a school). A reader should not have to
   find out from the code that one country is missing.
4. If a decision is reversed, add a new entry and mark the old one `superseded by Dn`.
5. When the user asks to review the log, list first the `default` and `provisional`
   decisions that many results depend on.

In short, AGENTS.md says: plan before longer tasks, do the smallest thing that answers the request, never delete (move files to _old/), never change raw data or your own files, work from the files and not from memory, quote word for word with the page, and keep a short progress note in status.md. Grow the file slowly. When the agent makes the same mistake twice, add one line.

Staying in charge: set the limits

The folder is a boundary. In Manual mode the agent asks before it reads or changes any file outside the project folder, and before it runs any command. Commands are the one gap: an approved command can reach anything you can. So read the paths before you allow a step. Do you see a folder outside your project, such as C:\Users\you\Desktop or ~/Documents/other-project? Click Deny and ask: “Why do you need to go outside the project folder?” Installing a program, as in Step 1.4, is the exception.

AGENTS.md adds a rule on top: work only inside this folder, and ask before going outside it.

Which permission mode? Stay in Manual for the first week: you see every step. After that, the choice is yours (Step 1.3 lists the modes). Accept edits follows a simple rule: free inside the project folder, permission everywhere else. Auto goes further: it works without routine questions, and a background check stops what it judges risky. Many experienced users work in Auto most of the time. Whatever you choose for routine work, go back to Manual when the work matters. If a project needs a second folder, add it with + next to the prompt box, then Add folder. Leave Bypass permissions alone: it switches off the questions altogether.

  1. The project. One question, six papers from four fields. Open the reading list.
  2. The folder, not the memory. Why the agent should work from files you give it, with page numbers, and not from what the model recalls. See What is an AI agent? in the overview.
  3. The ground rules you installed. Open AGENTS.md and the two skills, read-pdf and decision-log. They are plain text. Anyone can read them, and you can change them.
  4. Permissions. Manual for now. Later you choose: Accept edits or Auto for routine work, Manual when it matters (Step 2.1).
  5. Staying in charge. The four controls: limits, visibility, checks, and the final say. See the table at the end.

2.2 Collect the papers

In class · playtime

Every project starts with collecting material. Here the agent does the downloading and, more important, keeps a record of where each file came from. Start a new session and send:

Download the reading list from https://raw.githubusercontent.com/gabors-data-analysis/da-w-ai/main/friendly-agentic-ai-intro/starter/reading-list.md and save it as docs/reading-list.md.
Then download each paper on the list into docs/readings/, with the file name given. Try the PDF link first; if it fails, use the backup copy if there is one.
Check every file: is it really a PDF, and does its first page show the right title?
Write docs/readings/SOURCES.md: a table with the file name, the citation, the DOI, where you downloaded it from, today's date, and the licence.
Tell me which downloads failed and why. Do not try other websites.
Finally, make the PDFs read-only.

If you have time. The next prompt is slower, and it can wait until after class. Let the agent search on its own, with a tighter rule:

Find three more published papers on whether big events (sports, blackouts, disasters, holidays) change the number of births nine months later.
For each, give the full citation and a DOI, and open the DOI to check that it leads to that paper. Download a paper only if it is free to read.
Add them to docs/readings/SOURCES.md, marked "found by the agent". If you cannot confirm a paper, leave it out and say so.

It worked if the six papers open as papers in your PDF reader, and SOURCES.md lists them. If you ran the search, check the three new papers yourself: open each DOI in your browser and see that it leads to that paper.

Why the check that each file is really a PDF? When we prepared this pack, two of the downloads “succeeded” but saved a web page instead of a paper: one asked to enable JavaScript, the other said Oh no!. Both files were called .pdf. An agent that doesn’t check would happily summarize them.

Staying in charge: see what it did

You don’t have to take the agent’s word for what it did. After it creates or changes files, a Changes card shows the number of added and removed lines. Click it for the diff view: each changed file, with removed lines in red and added lines in green. It works like tracked changes in Word, for any file. You can also ask at any point: “List every file you created or changed in this session.”

To see every file read and every command run, switch the Transcript view to Verbose (press Ctrl+O to cycle through the views, or use the menu next to the session title).

2.3 Make an extract of each paper

In class · playtime

A good extract is a summary you can check. This time we agree on the checks before the work. Start a new session, switch the permission mode to Plan, and send:

Use the read-pdf skill on every PDF in docs/readings/.
For each paper, write docs/extracts/<file name>.md with: citation; research question; data (where, when, how many); method in one or two plain sentences; main finding; one sentence quoted word for word that states the main finding; the limitations the authors name. Give the page number for each item. If the paper does not state something, write "not stated". Do not use what you know about the paper from elsewhere.
Then write docs/extracts/overview.md: one table, one row per paper.
Before you start, tell me how you will check your own extracts.

Read the plan. A good answer includes at least this: every quote is searched for, word for word, in the extracted text, and every page number is checked. If the plan doesn’t say so, ask for it. Then switch back to Manual and let it go ahead.

Then check it yourself. Open docs/extracts/overview.md in Typora.

  1. Pick two papers. Open each PDF at the page given and search for the quoted sentence (Ctrl+F, or Cmd+F on a Mac). Is it there, word for word?
  2. Pick one paper and read its abstract. Does the extract say the same?
  3. Look at one “not stated”. Is it really not in the paper?

Why the fuss about quotes? Summarizing is what these models do best, and the table will look convincing. The typical mistake is a different one: a paraphrase presented as a quote, or a finding that comes from the model’s general knowledge and not from the file. A page number and a word-for-word quote make both mistakes easy to catch. In a published paper, a quote that doesn’t exist is the kind of error readers remember.

Staying in charge: agree the checks before the work

For work with text, three checks cover most mistakes: every quote is found word for word at the page given, every reference is a file in the folder or has a DOI that opens, and every number matches the table it comes from. For data, the checks are counts of observations, duplicates, value ranges and missing values (Step 2.6).

Then let the agent report by exception: it runs the agreed checks and tells you only about failures. But “no problems found” means only that the agreed checks passed. Keep your own hand check of two quotes. It takes five minutes, and it is the one check that doesn’t depend on the agent.

2.4 Ask the papers questions

In class · playtime

Now the folder is a small library, and you can ask it questions. Start a new session and try these, one at a time.

Using only docs/extracts/ and the papers in docs/readings/: which papers find more births after a big event, which find fewer, and which find no change? Group them, and give author, year and page for each claim.
Do the answers depend on how long the event lasts, an evening or several weeks? Use only the papers in this folder, with pages.

Then a test. Ask a question that the papers cannot answer:

What do these papers say about births in Argentina after the 2022 World Cup?

None of the papers covers it. The right answer is “not in the files”. If the agent answers anyway, from memory, you have just seen why the rule in AGENTS.md matters. Tell it, and ask where each claim came from.

Finally, ask for documentation. A folder of papers is only useful later if you know what is in it.

Write docs/readings/README.md: what this folder contains, how the extracts were made, a one-line description of each paper, and what the collection does not cover.

Staying in charge: the folder, not the memory

The model behind the agent is not a database. It doesn’t look facts up, it reconstructs them, so a reference or a number it “remembers” can be wrong. It is much stronger with material you put in front of it. So when you ask questions, say where the answer should come from (“using only the papers in docs/readings/”), and ask for the page. An answer you can trace to a page you can check. An answer from memory you can only believe.

Debrief

Ten minutes, together. Three questions.

  1. Did all six downloads work? Did anyone’s agent save a web page as a PDF, and did it notice?
  2. Did your two quotes check out? Was any “quote” a paraphrase, or on another page?
  3. What did the agent say about Argentina? Did it say “not in the files”, or did it answer from memory?

After class: Steps 2.5 and 2.6

About an hour, at your own pace. Step 2.5 finishes the project of this part. Step 2.6 is a separate assignment, on a new question, for those who work with data. Both are also the first step of Part 4, the guide to the weeks after.

2.5 Write the memo, review it, revise it

After class

This is the loop of every paper: a draft, comments, a revision. The agent writes the draft. You comment on it, on paper, as you would on a colleague’s draft. The agent sorts your comments, makes the language changes, and asks you about the rest.

Draft

Start a new session and send:

Write a one-page memo in docs/memo.md for a colleague in another field: "Do big events change when babies are born? What the research says."
Use only docs/extracts/ and the papers in docs/readings/. Cite as (Author year, p. X).
End with one paragraph on what this evidence cannot tell us.
Then convert it to docs/memo.docx.

If you have a Word file whose look you like, such as your university template, put it in docs/ and add: “Use docs/my-template.docx for the styles.” The agent copies its styles, not its text.

Review on paper

  1. Open docs/memo.docx in Word and save it as a PDF: File → Save As, then choose PDF as the file type. Call it memo.pdf.
  2. Open memo.pdf in your PDF reader: Microsoft Edge on Windows, Preview on a Mac, or Adobe Acrobat Reader anywhere.
  3. Read it as you would a colleague’s draft. Highlight text and add comments. Make at least three comments on language (a clumsy sentence, a word you would change) and at least two on content (a claim you doubt, a missing caveat, a paper that is misread).
  4. Save it as docs/memo_reviewed.pdf.

Revise

Read all comments, highlights and other annotations in docs/memo_reviewed.pdf (use pymupdf). List each one: the page, the marked text, and my comment.
Sort them into two groups: language and content.
Make the language changes in a copy of the memo, docs/memo_v2.md. Do not change the content yet.
Then ask me about each content comment, one at a time, and wait for my answer before you change anything.
When we are done, make docs/memo_v2.docx.

Then let Word show what changed. In desktop Word, go to the Review tab, click Compare, then Compare… (Windows) or Compare Documents (Mac). Choose memo.docx as the original and memo_v2.docx as the revised document. Word shows each change as a tracked change.

It worked if the agent’s list has every comment you made, the language changes changed only language, and the content changes are the ones you agreed to.

TipThe same loop on your own work

It works on any PDF with comments: a draft your coauthor marked up, a supervisor’s notes on a chapter, the proofs from a journal. It also works on a Word file with a coauthor’s tracked changes and comments: “List the tracked changes and comments in docs/draft_coauthor.docx, sorted into language and content.” But keep confidential material out of the folder until you have checked your data agreement (Step 1.2).

NoteWhy Markdown first, Word at the end? (click to open)

Right-click a Word file and open it with Notepad (on Windows). What you see is unreadable: a .docx is a packed bundle of files. Before the agent can work with it, it has to unpack and convert it, which costs time and loses some structure. A Markdown file reads the same in Notepad as in Typora. So we advise drafting and revising in Markdown with the agent, and converting to Word at the end. The idea comes from Simon Martin’s slides Jump-starting AI agents.

Staying in charge: keep the final say

The agent did the mechanical part: finding your comments, sorting them, fixing the language. The content decisions stayed with you, one at a time. It is your name on the memo, not the agent’s.

For anything that matters, add a second pair of eyes. The session that wrote a text is not its best judge: it remembers its own reasoning and tends to defend it. A new session has no such history. Start one and send: “You are reviewing docs/memo_v2.md, written by someone else. Check every citation against docs/extracts/ and the page given. List anything wrong or unsupported, most serious first. Do not change any files.”

2.6 A first task with data

After class · a separate assignment

This is a separate assignment. It leaves the papers behind: a new question, and numbers this time. The question is simple: in EU countries where more women work, do women also hold more seats in parliament? If you don’t work with data, you may skip this step. Part 3 shows data work at a much larger scale.

Start a new session and, before you send the prompt, switch the permission mode to Plan.

Using the World Bank's open data (its API, no key needed), get for all EU countries for 2023:
- the share of seats held by women in the national parliament (%)
- the female labor force participation rate (% of women aged 15 and over)

Save the raw download in data/raw, write the code in code/, and make one scatter plot (participation on the x axis, seats in parliament on the y axis, with country labels) saved in output/.
Then write a half-page memo in docs/memo_data.md: what the chart shows, and three caveats.
Keep the decision log as you go.

Read the plan, and say plainly if something looks off. When you are happy with it, switch back to Manual and tell the agent to go ahead.

Then check it. This is your job, not the agent’s.

  1. Open the chart. Are the countries where you expected them to be?
  2. Pick two countries and look up their numbers on data.worldbank.org. Do they match the CSV file in data/raw?
  3. Read DECISIONS.md. The World Bank has more than one measure of labor force participation. Which one did the agent pick, and did it tell you? Which countries had no 2023 data, and what did it do about them?
  4. Read the memo. Does it say “effect” or “causes”? It shouldn’t. A scatter plot of 27 countries shows an association.

If you find a mistake, tell the agent, and add a line to AGENTS.md if it could happen again.

Staying in charge: the choices it made without asking

Note what happened in check 3. The agent made a choice that you didn’t know existed. Nothing is wrong with that, as long as the choice is written down and you read it. This is what the decision log is for: read DECISIONS.md before you trust the results.

You don’t need to read Python to follow the code. What did you practise?

Four ways of staying in charge, each tied to a step.

What it means Where
Limits The agent works in one folder, asks before it acts, and never changes your originals Steps 2.1, 2.2
Visibility You can see every file it changed, every step it took and every choice it made Steps 2.2, 2.6
Checks You agree the checks before the work, you say where answers must come from, and you check a few things by hand Steps 2.3, 2.4, 2.6
The final say The agent does the mechanical part; you decide the content Step 2.5
NoteSix habits
  1. Plan first. For anything longer than a few minutes, use Plan mode. It is much cheaper to fix a plan than to fix finished work.
  2. Small steps. Ask for one thing, check it, then ask for the next. An agent running on a vague task produces plausible-looking work that you then have to read.
  3. Work from the folder. Put the material in the folder and ask the agent to use it, with pages. Don’t rely on what the model remembers.
  4. Check against the source. Compare a few numbers and a few quotes with the source by hand, every time.
  5. One session per task. Long sessions get muddled. What must carry over goes in a file: standing rules in AGENTS.md, analytical choices in DECISIONS.md, and where the work stands in status.md. End a session with “Update status.md.” Start the next with “Read status.md and continue where we left off.”
  6. Ask it to explain. “Why did you do that?” “What could go wrong here?” You are responsible for the work, so you need to understand it.

Troubleshooting

Problem What to do
The skills don’t show up when I type / Start a new session. Skills load when a session starts
A downloaded “PDF” won’t open, or shows a web page The site sent a web page instead of the paper. Ask the agent to use the backup copy, or download that paper yourself in the browser
A PDF comes out as nonsense, or nearly empty It is probably a scan. Tell the agent, and the read-pdf skill reads those pages as images. Check such papers with extra care
The agent finds none of my PDF comments Make sure you saved the PDF after commenting. Some readers keep comments in a separate file until you save
Word Compare shows changes everywhere The agent probably rebuilt the whole document. Ask it to start again from a fresh copy and change only the text
The agent seems stuck, or keeps doing the wrong thing Click stop and say plainly what you want. If the session is long, start a new one
It made a mess of my files Ask: “List every file you created or changed in this session.” Then ask it to move the unwanted ones to _old/
An error I don’t understand Paste it in and ask: “Explain this error simply, then fix it.”
